# 社区 Volcano v1.9 → v1.15 变更梳理

本文覆盖三部分：v1.10–v1.15 新增的主要功能、框架与 API 的重要改动、与 Kubernetes 1.19 的兼容性。

**说明：**
- 信息来源：社区各版本 release notes，以及对 `v1.9.0`…`v1.15.3` 各 tag 的源码比对。
- 内部 fork 的基线（社区 master `60a7f7536`，2024-08）已经包含 v1.10 的框架改动（`PredicateFn`、`Preemptive(queue, task)`、`Pipeline(evictionOccurred)`）。因此对内部迁移来说，**真正需要适配的破坏性改动集中在 v1.11–v1.15**。

|---|---|---|---|---|

| v1.10 | 2024-09 | 1.22 | 0.30 | 1.21 ~ 1.30 |

## 2. 主要新功能（按版本）

### v1.10
- 队列优先级：Queue 新增 `spec.priority`。
- capacity 插件成为默认的队列管理插件，支持按 GPU 型号做细粒度共享和回收。
  - 注意：capacity 与 proportion 不兼容，改用 capacity 后需要给队列设置 `deserved`。
- 支持 Pod Scheduling Readiness（`schedulingGates`），调度时跳过带 gate 的 Pod。
- Sidecar 容器（init 容器 `restartPolicy: Always`）的资源计算。
- vcctl 增强：支持 jobflow、jobtemplate、按队列过滤。
- 大规模性能优化：controller gate、共享 informer、减少 vcjob 更新。
- 收紧 RBAC，改进 Helm 安装与升级流程。

### v1.11
- **网络拓扑感知调度（预览）**：HyperNode 模型。
- **弹性层级队列**：capacity 插件支持 `parent` 层级、自动创建 root 队列，并引入 `VictimQueueOrderFn`。
- 多集群 AI 作业调度（Volcano Global）。
- 在离线混部：新增 vc-agent（超卖、QoS）和 network-qos。
- 负载感知重调度（descheduler）。
- 更细粒度的作业失败恢复策略：Pod 级 `RestartPod`、action 超时、`PodPending` 事件。
- Volcano Job 支持 PreemptionPolicy。
- Volcano Dashboard。

### v1.12
- **网络拓扑感知调度进入 Alpha**：
  - 新增 HyperNode CRD 和 hypernode 控制器（UFM/label 自动发现）。
  - 新增 `network-topology-aware` 插件。
  - Job 和 PodGroup 新增 `networkTopology` 字段。
- vGPU 动态 MIG 切分。
- DRA（Dynamic Resource Allocation）支持。
- Volcano Global 支持队列容量管理。
- Gang 调度扩展到更多工作负载类型（Deployment、StatefulSet 等）。
- JobFlow 增强；多租户下更细粒度的权限控制。
- 升级注意：
  - PodGroup mutating webhook 默认关闭。
  - 队列状态校验从 Pod 创建阶段移到 PodGroup 创建阶段。
  - scheduler 的 pprof 默认关闭。

### v1.13
- 支持 LeaderWorkerSet（大模型推理场景）。
- Cron VolcanoJob：新增 `batch.volcano.sh` CronJob CRD 和控制器。
- 基于节点 label 自动发现 HyperNode。
- 原生 Ray 支持；HCCL 插件（昇腾集合通信）。
- NodeGroup 增强。
- **ResourceStrategyFit 插件**：按资源类型独立打分，并支持稀缺资源规避（SRA）。
  - 原先在 predicates 插件里的 proportional 逻辑迁到了这个插件。
- **拓扑感知抢占**：参照 kube-scheduler 的 DryRun 做候选节点选择，引入 `Simulate*` hook。
- 混部与操作系统解耦；支持自定义超卖资源名。

### v1.14
- **多调度器与动态节点分片（Alpha）**：新增 NodeShard CRD 和 sharding 控制器。
- **AI Agent 快速调度（Alpha）**：新增 `vc-agent-scheduler`，按 Pod 粒度、多 worker 调度。
- 网络拓扑感知增强：
  - HyperNode 级 binpack。
  - **SubGroupPolicy**（子组级拓扑约束和 gang）。
  - Job 级加 SubGroup 级的多层 gang。
- Volcano Global：HyperJob（多集群训练）、数据感知调度。
- 通用操作系统上的混部：CPU Throttling、Memory QoS、CPU Burst、Cgroup V2；新增 ColocationConfiguration CRD。
- **昇腾 vNPU 调度**：支持 MindCluster 和 HAMi 两种模式，覆盖 310P/910。
- 支持原地更新 Pod（In-place Pod Update）。
- 可选的 ValidatingAdmissionPolicy/MutatingAdmissionPolicy；CRD 增加 CEL 校验。
- `volcano.sh/apis` 并入主仓库的 staging 目录。

### v1.15
- **Gang 感知的抢占与回收（Alpha）**：新增 `gangPreempt` / `gangReclaim` 两个 action，以及 `UnifiedEvictableFn` hook。
  - 按 job/gang 粒度选择 victim。
  - 支持按 HyperNode 范围搜索。
  - 抢占结果通过 nomination 交给 allocate 快速落地。
- **capacity 插件支持 DRA 队列配额**：ResourceClaim 计入 capability/deserved/guarantee；DRA 默认开启。
- 可插拔的多分片策略（Alpha）：filter/score/select 三阶段，ConfigMap 支持热更新。
- 基准测试与性能观测工具。
- **调度门控做队列准入（Alpha）**：注解 `scheduling.volcano.sh/queue-allocation-gate`，避免集群自动扩缩容因配额不足而误扩容。
- NodeGroup 支持按 preferred 列表顺序打分；capacity 新增 `ancestorReclaimLevel` 参数。
- GPU 独占规则、vGPU 抢占；PodLevelResources。
- `--resource-sync-timeout`：启动时等待事件 handler 完成初始同步。
- 支持 k8s 1.35；修复 webhook 请求体过大导致 OOM 的漏洞 CVE-2026-44247。

## 3. 框架与 API 重要改动

### 3.1 调度框架（`pkg/scheduler/framework`）

**`Plugin` 和 `Action` 接口在 v1.9–v1.15 期间没有变化。** 新增的能力都通过 session hook 和可选接口暴露。

| 版本 | 改动 | 对内部 fork 的影响 |
|---|---|---|
| v1.10 | `PredicateFn` 返回值从 `([]*Status, error)` 改为 `error`；`Preemptive(queue, candidate)`；`Pipeline(..., evictionOccurred)`；`Binder.Bind` 返回 `map[TaskID]string`；`UpdatePodCondition` 改为 `UpdatePodStatus` | 内部基线已包含，无需处理 |
| v1.11 | `AddVictimQueueOrderFn`；`BuildVictimsPriorityQueue` 新增 preemptor 参数；`Event.Err`；`Statement.UnAllocate`；session 新增 `VCClient()` | 部分已包含 |
| v1.12 | **删除卷绑定相关接口**（`GetPodVolumes`/`AllocateVolumes`/`BindVolumes`/`VolumeBinder`，以及 `TaskInfo.PodVolumes`），改为 predicates 插件通过 VolumeBinding 加 PreBinder 完成；**`AddBindTask(*BindContext)` + `PreBinder` + `RegisterBinder`**；可选接口 `BindContextHandler`；`PodGroupOldState`；`cycleStatesMap`/`GetCycleState`；hypernode 相关的 session 字段；`AddHyperNodeOrderFn`；`SaveOperations`/`RecoverOperations` | 内部已 backport 绑定流程，可以改用社区实现 |
| v1.13 | `AddSimulate{AddTask,RemoveTask,Predicate,Allocatable}Fn`；`LessEqualWithDimension` 改为 `LessEqualWithDimensionAndResourcesName`；`GetUnschedulableAndUnresolvableNodesForTask` 改名为 `FilterOutUnschedulableAndUnresolvableNodesForTask`；`HierarchyEnabled()` | Simulate* 内部已 backport |
| v1.14 | **引入 SubJob**：`AddSubJob{Ready,Pipelined,Order}Fn`、`AddHyperNodeGradientFor{Job,SubJob}Fn`；`HyperNodeOrderFn` 参数改为 `*SubJobInfo`；**k8s fwk 接口化**（`CycleState`、`NodeInfo` 改用 `k8s.io/kube-scheduler/framework` 中的接口，`NodeMap` 改为 `map[string]fwk.NodeInfo`）；`SaveOperations` 改为包级函数；`MarkJobDirty`/`DirtyJobs`；`NodesInShard` | 影响大：Simulate*、archimedes、predicates 相关代码都要改 |
| v1.15 | **`Statement.Evict` 不再返回 error**；新增 `Statement.Merge(...)`，**删除 `UnAllocate`**；**`Preemptive(queue, []*TaskInfo)`**；`AddUnifiedEvictableFn` 和 `EvictionContext`；`HyperNodeGradient*Fn` 新增 `SearchPurpose` 参数；`NodeReduceFn` 使用 `fwk.NodeScoreList` | 影响大：内部的 Evict 错误处理、UnAllocate、Preemptive 的调用点都要改 |

**PluginOption 新增的开关：**
- v1.12：`enabledHyperNodeOrder`
- v1.14：`enabledSubJobReady`、`enabledSubJobPipelined`、`enabledSubJobOrder`、`enabledHyperNodeGradient`

`VictimQueueOrder`、`UnifiedEvictable`、`Simulate*` 没有对应开关，插件只要注册就会被调用。

## 4. 与 Kubernetes 1.19 的兼容性

### 4.1 结论

- 官方：v1.15 支持 k8s 1.23–1.35，**不支持 1.19**。最后一个支持 1.19 的版本是 v1.8。
- 实际：通过配置调整加少量补丁，**大概率可以运行**，但没有社区测试覆盖，需要用 `kindest/node:v1.19.x` 跑一轮 e2e 验证。
- **默认配置下会直接卡住的只有一处**：scheduler 的 PDB `policy/v1` informer。1.19 上 LIST 返回 404，`WaitForCacheSync` 会一直阻塞，调度循环永远不会开始。
- **DRA 和 WatchList 会自动关闭的原因**：scheduler 和 webhook-manager 启动时会调用 `SetupComponentGlobals`（`pkg/util/util.go`），把 feature gate 的模拟版本（emulation version）设为 apiserver 的版本 1.19。controller-manager 不会调用这个函数。
- 内部 fork 目前同样会注册 `policy/v1` PDB informer，并没有做过 1.19 适配。从部署清单目录 `k8s-v121` 看，它实际面向的是 **1.21 及以上**。**需要先确认线上集群的实际版本。**

### 4.2 不兼容项

| 组件 | API/功能 | 所需 k8s | 在 1.19 上的表现 | 处理方式 |
|---|---|---|---|---|
| scheduler（及 agent-scheduler） | `policy/v1` PDB informer（gate `PodDisruptionBudgetsSupport` **默认开启**，`cache/cache.go:645`） | 1.21 | **直接卡住**：cache 永远无法同步 | `--feature-gates=PodDisruptionBudgetsSupport=false`，并去掉 `pdb` 插件；或打补丁回退到 `policy/v1beta1` |
| scheduler | `storage/v1beta1` CSIStorageCapacity | 1.21 | 开启时卡住；**默认关闭** | 保持 `CSIStorage` 和 `--csi-storage` 关闭 |
| scheduler | DRA（`resource.k8s.io/v1`） | 1.34 | 在模拟版本 1.19 下自动关闭 | 不要打开 `capacity.DynamicResourceAllocationEnable`，也不要绕过 `SetupComponentGlobals` |
| controller-manager | client-go 0.35 的 WatchListClient（默认开启） | 服务端 1.27+ | 理论上会回退到普通 LIST，**未验证** | `--feature-gates=WatchListClient=false` |
| CRD、scheduler | HyperNode CRD 中的 CEL（`x-kubernetes-validations`）；scheduler **无条件**注册 HyperNode informer | CEL 需要 1.25 | 客户端校验可能报错；装上后规则会被静默忽略，校验失效。**如果没装这个 CRD，scheduler 会卡住** | 安装前去掉 CEL 规则（或使用 `--validate=false`），确保所有 CRD 都已安装；打补丁在 webhook 里补回校验 |
| 安装器 | ValidatingAdmissionPolicy / MutatingAdmissionPolicy | 1.30 / 1.34 | 资源创建失败 | 保持 `vap_enable`、`map_enable` 为 false（默认值） |
| webhook、scheduler | `SchedulingGatesQueueAdmission`（`spec.schedulingGates`） | 1.26+ | 默认关闭；打开后 1.19 会静默丢弃该字段，功能失效 | 保持关闭 |
| controller-manager | 队列状态更新使用 server-side apply（`ApplyStatus`） | 1.22 GA（1.18 起 Beta） | 正常情况下可用；如果集群关闭了 SSA，队列状态不会更新 | 实测确认；或打补丁回退到 `UpdateStatus` |
| Helm 模板 | Service 的 `ipFamilyPolicy` | 1.20 | 只有显式设置时才会渲染 | 不要设置 |
| scheduler、webhook | sidecar、PodLevelResources、原地扩缩容 | 1.27+ | 1.19 上没有这些字段，相关逻辑不会触发 | 无需处理 |

**在 1.19 上没问题的部分：**
- `storage.k8s.io/v1` 的 StorageClass、CSINode、CSIDriver、VolumeAttachment
- `scheduling.k8s.io/v1` PriorityClass
- `coordination.k8s.io/v1` Lease
- `admissionregistration/v1` webhook（未使用 matchConditions）
- `apiextensions/v1` CRD
- `batch/v1` Job
- `apps/v1`

**另外：** 在模拟版本 1.19 下，不要给 scheduler 和 webhook 传 kube 自带的 feature gate，只传 Volcano 自己的 gate。

### 4.3 在 1.19 上运行的最小改动

**只改配置：**
1. scheduler：加 `--feature-gates=PodDisruptionBudgetsSupport=false`，并从调度配置中去掉 `pdb` 插件。
2. 保持 `CSIStorage`、`--csi-storage`、`SchedulingGatesQueueAdmission` 关闭。
3. controller-manager：加 `--feature-gates=WatchListClient=false`。
4. Helm：`vap_enable`/`map_enable` 设为 false，不设置 `ipFamilyPolicy`；HyperNode 等 CRD 去掉 CEL 后全部安装。
5. 启动后检查日志：确认 emulationVersion 已设为 1.19，且没有 `policy/v1`、`resource.k8s.io` 相关的 LIST 失败。

**建议的代码补丁：**
1. 注册 PDB、CSIStorageCapacity、DRA 的 informer 之前，先通过 discovery 检查 API 是否存在；PDB 回退到 `policy/v1beta1`。
2. 给 `WaitForCacheSync` 加超时，并在日志中打印哪些 informer 没有同步完成。
3. 在 webhook 中补回 HyperNode 的 selector 校验（因为 1.19 上 CEL 不生效）。
4. controller-manager 也调用 `SetupComponentGlobals`。
5. 队列状态更新在 `ApplyStatus` 失败时回退到 `UpdateStatus`。

### 4.4 内部特有组件与 1.19

- archimedes-scheduler 本身基于 k8s 1.19.9，只用到 1.19 已有的 API（PV、PVC、StorageClass、NRT 和 Reservation CRD）。**和集群版本没有冲突。**
- **真正的问题在编译期**：它依赖 1.19 版本的调度框架，而社区 v1.15 使用的是 k8s 1.35 的 fwk 接口，两者需要做适配或剥离（见 `v1.15-feature-inventory.md` 第 2 节）。
