## 2. 迁移前必须先决策的事项

### 2.1 k8s 1.30 → 1.35 的框架接口变化

社区把 `CycleState` 和 `NodeInfo` 改成了接口（`fwk.*`），内部所有 Simulate\*、archimedes 和 predicates 相关代码都受影响。

### 2.2 archimedes-scheduler 依赖 k8s 1.19 调度框架

涉及外部模块 `coding.jd.com/k8s-dev/archimedes-scheduler-1.19` 和 `k8s.io/kube-scheduler v0.19.9`，另外还内嵌了约 12k 行代码。

**可选方案**：
- 先升级 archimedes
- 剥离成独立仓库
- 改写为社区新框架下的插件

### 2.3 框架签名冲突

| 内部签名 | 社区签名 |
|---|---|
| `ssn.Overused(queue, req)` | `ssn.Overused(queue)` |
| `ssn.Preemptive(queue, job\|task)` | `Preemptive(queue, []*TaskInfo)` |
| `Plugin` 接口新增 `OnSessionPreClose` | 社区没有 |

### 2.4 行为语义差异

直接采用社区代码会**静默改变线上行为**：

| 差异点 | 内部 | 社区 |
|---|---|---|
| `GetPodPreemptable` 未标注默认值 | `false` | `true`（`api/pod_info.go`） |
| `Resource.Sub` 断言 | 去掉了断言 | 保留断言 |
| 可抢占判定粒度 | 按 Job 判定（ReclaimAble / Preemptable / Elasticable） | 按 task 级 `task.Preemptable` |

### 2.5 昇腾插件以 Go plugin .so 方式加载

当前用 `-v v1.9.0` 构建，需要 mind-cluster 侧同步适配社区 v1.15 的框架接口。

### 2.6 安全问题

仓库中提交了以下凭据，迁移时**不要带入新仓库，并轮换**：

- `id_rsa`、`pkg/scheduler/archimedes-scheduler/hack/id_rsa`（及 `.pub`）
- `Dockerfile.mindcluster` 里写死的 `PRIVATE-TOKEN`

## 3. 功能清单

> **难度标记**：低 / 中 / 高
> **生产**：✅ 表示线上已启用（依据 `kuper-system/volcano-scheduler-configmap`，2026-10-14 提供）
> **注意**：仓库内 `manifests/*/scheduler-configmap.yaml` 和 `.claude/docs/volcano-ea-scheduler-flow.md` 中的配置都已过时。线上 actions 为 `reserve, allocate, reclaim, preempt, backfill`（不含 enqueue）。

### 3.1 配额、抢占与回收语义（业务核心）

#### 3.1.1 Job 业务属性和"全局可抢占"语义

- **功能**：由 JobProperty/JobType 推导 ReclaimAble、Preemptable、Elasticable
- **代码**：`api/job_info.go`（`setDefaultPreemptProperty`）、`api/constants.go`、tdm
- **配置**：`scheduling.k8s.io/{task_type,task_property,preemptable,reclaimable,elasticable,priorityClassName}`，label `job-property`
- **社区对应**：无，社区按 task 级 Preemptable
- **难度**：高 | **生产**：✅

#### 3.1.2 capacity 不可抢占配额

- **功能**：不可抢占作业受 deserved 约束，可抢占作业受 capability 约束；弹性作业拆成 min/max 两部分校验
- **代码**：`plugins/capacity`
- **配置**：`capacity.enable.global.preempt`
- **社区对应**：无，社区 capacity 已重写为层级队列 + DRA
- **难度**：高 | **生产**：✅

#### 3.1.3 Gang 感知超用检查

- **功能**：把作业 min 请求或副本单元计入队列超用判断，并写 PodGroup 条件 NotEnoughQuota/WaitingForMin
- **代码**：allocate/preempt/reclaim，capacity/proportion/extender
- **配置**：`overusedCheckGangEnable`
- **社区对应**：无，签名冲突
- **难度**：高 | **生产**：✅

#### 3.1.4 排队原因回写

- **功能**：`OnSessionPreClose` 重放 Overused，改写 PendingReason
- **代码**：capacity、framework
- **配置**：`scheduling.k8s.io/{notEnoughQuota,notEnoughMin,lastReason,...}`
- **社区对应**：无
- **难度**：中 | **生产**：✅

#### 3.1.5 同队列高优抢占低优

- **功能**：限定 preemptor 准入，Job 级 victim 过滤
- **代码**：`actions/preempt`、`plugins/property`（`task-property`）
- **配置**：队列注解 `scheduling.k8s.io/enablePreemptLowPriority`，`enable.preempt`
- **社区对应**：社区 priority 可部分替代
- **难度**：中高 | **生产**：✅

#### 3.1.6 relaxEvictByJob

- **功能**：同队列按整 Job 腾配额，要求 GPU 类型一致
- **代码**：`actions/preempt/relax.go`
- **配置**：`enableRelaxEvictByJob`（代码默认 true，注释写 false）
- **社区对应**：无
- **难度**：中 | **生产**：✅（线上未显式配置，按代码默认值 true 生效）

#### 3.1.7 online 队列保持饥饿态

- **功能**：online 队列跳过配额抢占
- **代码**：gang、capacity
- **配置**：`volcano.sh/queue.skipQuotaPreempt`，队列名 `online-queue`
- **社区对应**：无
- **难度**：中 | **生产**：✅

#### 3.1.8 弹性作业只牺牲超出 min 的副本

- **代码**：`plugins/elastic`
- **配置**：`scheduling.k8s.io/elasticable`
- **社区对应**：社区 gang 已覆盖大部分

#### 3.1.9 弹性推理作业 ≥1 个副本即视为 ready

## 5. 建议迁移顺序

1. **基础层**
   - 把 Reservation 类型加入社区 staging
   - api 扩展字段和常量，以及 eaframework 依赖
   - framework 新增回调，并敲定 `Overused` / `Preemptive` 签名
   - Statement 扩展，`OnSessionPreClose`
   - 先决定日志工具是整体迁移，还是退回 klog
2. **低难度、独立插件**：slanode、reserve、coordinator、net-topology、elastic、cooldown、redis，以及 priority、task-topology、extender 的小补丁。spblock、node-pool 和 usage 的磁盘/网络感知线上都没有启用，可以暂缓或不迁
3. **业务核心**：先迁 capacity 语义和全局可抢占语义，再迁 preempt/reclaim 的 victim 过滤、relaxEvictByJob、queue-reclaim、notebook、task-property。最后迁 allocate 中的 Gang 超用检查和 PodGroup 条件（allocate 需要在社区新的 worksheet 结构里重写）
4. **高难度模块**：jobbackoff、delay-schedule、replica-gang（先评估能否改写到 SubGroupPolicy）、Reservation 全链路、SuperPod 拓扑路径。这几项线上都已启用，都是必须迁移的
5. **外部依赖**：archimedes 升级或剥离、mind-cluster 昇腾插件适配 v1.15、比例预留迁到 `resource-strategy-fit` 并转换配置格式
6. **可观测性和性能**：metrics 去重，session 跳过机制，日志聚合

### 7.4 迁移到社区 v1.15 时需要改写的配置

| 线上配置 | 社区 v1.15 的情况 | 处理方式 |
|---|---|---|
| `predicates` 的 `predicate.ProportionalEnable` / `predicate.resources.*` | 社区已移到 `resource-strategy-fit` 插件，格式为 `proportional.*`，且不支持 zone 和卡型映射 | 二选一：在 predicates 中保留内部实现，或者扩展 `resource-strategy-fit` |
| 插件级开关 `enableBackoffCheck`、`enableSchedulingUnit`、`enableVictimProtection`、`enableCoeviction` | 社区 `PluginOption` 中没有这些开关 | 需要随框架扩展一起迁移 |
| 拓扑感知抢占 `enableTopologyAwarePreemption` 等 | 社区有同名 key，但语义不同：社区对所有作业生效，内部只对 SuperPod 作业生效 | 要么改名，要么保证迁移后仍只对 SuperPod 作业生效 |
