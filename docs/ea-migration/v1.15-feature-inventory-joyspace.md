## 2. 迁移前必须先决策的事项

### 2.1 k8s 1.30 → 1.35 的框架接口变化

社区把 `CycleState` 和 `NodeInfo` 改成了接口（`fwk.*`），内部所有 Simulate\*、archimedes 和 predicates 相关代码都受影响。

### 2.2 archimedes-scheduler 依赖 k8s 1.19 调度框架

涉及外部模块 `coding.jd.com/k8s-dev/archimedes-scheduler-1.19` 和 `k8s.io/kube-scheduler v0.19.9`，另外还内嵌了约 12k 行代码。

**可选方案**：
- 先升级 archimedes
- 剥离成独立仓库
- 改写为社区新框架下的插件

### 2.3 框架签名冲突

| 内部签名 | 社区签名 |
|---|---|
| `ssn.Overused(queue, req)` | `ssn.Overused(queue)` |
| `ssn.Preemptive(queue, job\|task)` | `Preemptive(queue, []*TaskInfo)` |
| `Plugin` 接口新增 `OnSessionPreClose` | 社区没有 |

### 2.4 行为语义差异

直接采用社区代码会**静默改变线上行为**：

| 差异点 | 内部 | 社区 |
|---|---|---|
| `GetPodPreemptable` 未标注默认值 | `false` | `true`（`api/pod_info.go`） |
| `Resource.Sub` 断言 | 去掉了断言 | 保留断言 |
| 可抢占判定粒度 | 按 Job 判定（ReclaimAble / Preemptable / Elasticable） | 按 task 级 `task.Preemptable` |

### 2.5 昇腾插件以 Go plugin .so 方式加载

当前用 `-v v1.9.0` 构建，需要 mind-cluster 侧同步适配社区 v1.15 的框架接口。

### 2.6 安全问题

仓库中提交了以下凭据，迁移时**不要带入新仓库，并轮换**：

- `id_rsa`、`pkg/scheduler/archimedes-scheduler/hack/id_rsa`（及 `.pub`）
- `Dockerfile.mindcluster` 里写死的 `PRIVATE-TOKEN`
