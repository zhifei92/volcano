## 2. 迁移前必须先决策的事项

1. **k8s 1.30 → 1.35 的框架接口变化。** 社区把 `CycleState` 和 `NodeInfo` 改成了接口（`fwk.*`），内部所有 Simulate*、archimedes 和 predicates 相关代码都受影响。
2. **archimedes-scheduler 依赖 k8s 1.19 调度框架。** 涉及外部模块 `coding.jd.com/k8s-dev/archimedes-scheduler-1.19` 和 `k8s.io/kube-scheduler v0.19.9`，另外还内嵌了约 12k 行代码。可选方案：先升级 archimedes，或者剥离成独立仓库，或者改写为社区新框架下的插件。
3. **框架签名冲突。**
   - 内部 `ssn.Overused(queue, req)` 对应社区 `ssn.Overused(queue)`。
   - 内部 `ssn.Preemptive(queue, job|task)` 对应社区 `Preemptive(queue, []*TaskInfo)`。
   - 内部在 `Plugin` 接口上新增了 `OnSessionPreClose`，社区没有。
4. **行为语义差异。** 直接采用社区代码会静默改变线上行为：
   - `GetPodPreemptable` 未标注时的默认值：内部是 `false`，社区是 `true`（`api/pod_info.go`）。
   - `Resource.Sub`：内部去掉了断言，社区保留断言。
   - 可抢占判定粒度：内部按 Job 判定（`ReclaimAble` / `Preemptable` / `Elasticable`），社区仍按 task 级的 `task.Preemptable`。
5. **昇腾插件（mind-cluster `ascend-for-volcano`）以 Go plugin `.so` 方式加载。** 当前用 `-v v1.9.0` 构建，需要 mind-cluster 侧同步适配社区 v1.15 的框架接口。
6. **安全问题。** 仓库中提交了以下凭据：
   - `id_rsa`、`pkg/scheduler/archimedes-scheduler/hack/id_rsa`（及 `.pub`）
   - `Dockerfile.mindcluster` 里写死的 `PRIVATE-TOKEN`

   迁移时不要带入新仓库，并轮换这些凭据。

## 3. 功能清单

难度标记：低 / 中 / 高。"生产"一列依据线上 `kuper-system/volcano-scheduler-configmap`（2026-10-14 提供，详见第 7 节）。仓库内 `manifests/*/scheduler-configmap.yaml` 和 `.claude/docs/volcano-ea-scheduler-flow.md` 中的配置都已过时。

线上 actions 为 `reserve, allocate, reclaim, preempt, backfill`（不含 enqueue）。

## 5. 建议迁移顺序

1. **基础层。**
   - 把 Reservation 类型加入社区 staging。
   - api 扩展字段和常量，以及 eaframework 依赖。
   - framework 新增回调，并敲定 `Overused` / `Preemptive` 签名。
   - Statement 扩展，`OnSessionPreClose`。
   - 先决定日志工具是整体迁移，还是退回 klog。
2. **低难度、独立插件。** slanode、reserve、coordinator、net-topology、elastic、cooldown、redis，以及 priority、task-topology、extender 的小补丁。spblock、node-pool 和 usage 的磁盘/网络感知线上都没有启用，可以暂缓或不迁。
3. **业务核心。** 先迁 capacity 语义和全局可抢占语义，再迁 preempt/reclaim 的 victim 过滤、relaxEvictByJob、queue-reclaim、notebook、task-property。最后迁 allocate 中的 Gang 超用检查和 PodGroup 条件（allocate 需要在社区新的 worksheet 结构里重写）。
4. **高难度模块。** jobbackoff、delay-schedule、replica-gang（先评估能否改写到 SubGroupPolicy）、Reservation 全链路、SuperPod 拓扑路径。这几项线上都已启用，都是必须迁移的。
5. **外部依赖。** archimedes 升级或剥离、mind-cluster 昇腾插件适配 v1.15、比例预留迁到 `resource-strategy-fit` 并转换配置格式。
6. **可观测性和性能。** metrics 去重，session 跳过机制，日志聚合。

### 7.4 迁移到社区 v1.15 时需要改写的配置

| 线上配置 | 社区 v1.15 的情况 | 处理方式 |
|---|---|---|
| `predicates` 的 `predicate.ProportionalEnable` / `predicate.resources.*` | 社区已移到 `resource-strategy-fit` 插件，格式为 `proportional.*`，且不支持 zone 和卡型映射 | 二选一：在 predicates 中保留内部实现，或者扩展 `resource-strategy-fit` |
| 插件级开关 `enableBackoffCheck`、`enableSchedulingUnit`、`enableVictimProtection`、`enableCoeviction` | 社区 `PluginOption` 中没有这些开关 | 需要随框架扩展一起迁移 |
| 拓扑感知抢占 `enableTopologyAwarePreemption` 等 | 社区有同名 key，但语义不同：社区对所有作业生效，内部只对 SuperPod 作业生效 | 要么改名，要么保证迁移后仍只对 SuperPod 作业生效 |
